# Отчёт о рефакторинге MEXC Spread Bot

## Основание

Переработан код из пользовательского архива `mexc-spread-bot-main.zip`. GitHub-репозиторий не изменялся, сервер не обновлялся, реальные торговые операции не выполнялись.

Исходник: `src/spred.cpp`, 6 964 строки, SHA256 `2d47816c077920f7265643429a73b739b1f34d5c7da0e7b2748bcaad30eaf632`.

## Что изменено

1. Монолит заменён 22 файлами реализации и 28 заголовками. `main` теперь только передаёт управление приложению.
2. Методы HTTP/WebSocket, REST, paper-движка, live-исполнения и учёта вынесены из определений классов в отдельные `.cpp`.
3. Отдельно выделены стратегия одного символа, обработка очереди событий, периодические и итоговые отчёты.
4. Неявные захваты больших лямбд заменены явным контекстом `SessionOptions`.
5. Общее состояние получает одно определение в соответствующем `.cpp`; функции размещены в пространстве имён `spred`.
6. Makefile поддерживает раздельную инкрементальную сборку и отслеживание зависимостей заголовков. Добавлены `make check` / `make test`, предупреждения `-Wall -Wextra` и шаг офлайн-регрессии в GitHub Actions.
7. README на русском и английском обновлены. Архитектура и историческое описание конфигурации сохранены в `docs/`.
8. Добавлен воспроизводимый офлайн-стенд с исходной версией как эталоном. Сжатый эталон хранится только в `tests/reference/`, не используется рабочим ботом.

## Проверки

В локальной Linux-среде GCC/OpenSSL успешно выполнены:

| Проверка | Результат |
|---|---|
| Чистая сборка C++17, `-O2 -Wall -Wextra` | Успешно, без предупреждений |
| 95 проверок функций и моделей | Пройдены новой и исходной версиями |
| 50 детерминированных траекторий учёта по 100 сделок | Снимки результатов совпали точно |
| 3 сценария raw-replay, по 1000 синтетических кадров | Выводы совпали после нормализации только меток настенных часов |
| Отказ без live-ключей | Код завершения 2 у обеих версий |
| Отказ без подтверждения live | Код завершения 2 у обеих версий |
| Более 10 символов вне replay | Код завершения 1 у обеих версий |
| Несуществующая запись replay | Код завершения 1 у обеих версий |
| Независимая компиляция 28 публичных заголовков | Пройдена |
| Синтаксис 9 Python-утилит и 7 Bash-скриптов | Пройден |

95 проверок включают 50 траекторий учёта: это не 145 отдельных тестов. Синтаксическая проверка Python/Bash не равна проверке всех их функций.

Три replay-сценария: исходные параметры; пессимистическая очередь со случайной задержкой; отключённый print-фильтр с вероятностью исполнения внутренних принтов и логированием сделок. Изменения параметров действуют только внутри тестового стенда.

Сеть в исполняемых тестовых процессах блокируется через `LD_PRELOAD`. Ответ метаданных символа подменяется локальным mock-curl; используются синтетические рыночные кадры и фиктивные данные. Проверки live останавливаются до сетевой работы, без live-подтверждения.

## Что намеренно не менялось

Не пересматривались торговые формулы, риск-параметры, порядок исполнения стратегии, протокол сообщений, аргументы CLI, имена `MM_*`, формат raw-записи и формат отчётов. Python/Bash-инструменты и результаты исследований сохранены. Это структурная переработка, не разработка прибыльной стратегии.

Совпадение на перечисленных сценариях — ограниченное свидетельство совместимости, а не математическое доказательство одинакового поведения при любых данных. Реальные API, приватный WebSocket, reconnect, сетевые аварии и многопоточность в боевой среде здесь не проверялись.

## Сборка на Windows

Проект использует POSIX/Linux API. В PowerShell нельзя просто выполнить Linux-команду компиляции: установите/откройте WSL2 с Ubuntu и выполняйте `make -j2` и `make check` внутри Linux. Готовый Windows `.exe` не предоставляется.

## Как использовать результат

1. Распакуйте архив в отдельный каталог, не поверх работающей копии.
2. Выполните `make -j2`, затем `make check` в Linux/WSL2.
3. Изучите `docs/ARCHITECTURE.md`. Для собственного сравнения используйте paper/replay, а не реальные средства.
4. Только после самостоятельной проверки переносите исходники в отдельную ветку своего репозитория. Реальные `.env`, ключи и рабочие данные не коммитьте.

Бинарники и временные тестовые данные в комплект не входят. Включены исходники, тесты, исходные публичные результаты исследований и документация.

Это отдельные изменения поведения/жизненного цикла, требующие отдельного набора проверок.
